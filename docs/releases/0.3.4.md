# Uno Lab 0.3.4

Uno Lab can actually take the assistant role now. 0.3.3 could not.

## What's fixed

Android decides whether an app may hold the assistant role with `AssistantRoleBehavior`, which rejects a package unless all three of these are declared:

```java
if (sessionService == null || recognitionService == null || !supportsAssist) return false;
```

0.3.3's `voice_interaction.xml` had the session service and `supportsAssist` but **no recognition service**, so the system answered:

```text
AssistantRoleBehavior: Package com.everettpenne.unolab has an unqualified voice interaction service
RoleControllerServiceImpl: Package does not qualify for the role
```

and the role could not be granted at all — neither from Model › "Make Uno Lab the assistant", nor from Settings.

0.3.4 declares a recognition service. It is a stub and nothing ever asks it to listen: there is no hotword, because `CAPTURE_AUDIO_HOTWORD` is privileged and a sideloaded app cannot hold it. Verified on a Pixel 10a running GrapheneOS: with the stub in place, `cmd role add-role-holder android.app.role.ASSISTANT` succeeded where it had failed.
