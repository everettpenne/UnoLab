# Uno Lab 0.3.3

Uno Lab can be the phone's assistant — and see the screen to answer about it.

## What's changed

- **A system assistant role.** Model › "Make Uno Lab the assistant" asks Android for the assistant role (GrapheneOS offers it; no Google app holds it). Once granted, the assist gesture opens Uno's search from any app.
- **What's on the screen becomes a fact for the answer.** The session reads the screen's text once, drops password fields, caps it at 6,000 characters, and hands it to Uno's search with the question. It is treated as written by another app: quoted, only used when the question points at the screen, never with a request that could become an action, and never stored.
- Uno Lab holds the role rather than the launcher because this app has **no INTERNET permission** — screen text lands in the one app that cannot send it anywhere.
- **No hotword.** "Hey Qwen" needs `CAPTURE_AUDIO_HOTWORD`, which is privileged and unavailable to a sideloaded app. The gesture, or Uno's own search, is how it opens, and the row in Model says so.

## Notes: what this has and hasn't been tested on

Unit tests cover the screen-text cap and the joining of repeated labels. **Not tested on a phone for this release**: the role being offered, the gesture reaching the session, and the hand-off into Uno Launcher's search — all of it needs a device with the role granted.

Taking the role lets this app read the screen of the app in front. Nothing else changes: without the role, Uno Lab answers exactly as before, and the launcher's own search still works.
